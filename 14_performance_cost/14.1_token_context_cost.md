## 14.1 Chi phí Token & Chi phí ngữ cảnh (Context Cost)

Mức tiêu thụ Token là yếu tố trực tiếp thúc đẩy chi phí của hệ thống Agent. Mục này tiếp cận từ các chiều kích: Luồng vào/ra của Token, chiến lược tinh gọn prompt, nén ngữ cảnh..., cung cấp phương án tối ưu hóa có hệ thống dựa trên cấu hình của OpenClaw.

### 14.1.1 Ba giai đoạn luân chuyển của Token

Trong một phiên đối thoại hoàn chỉnh của Agent, việc tiêu thụ Token chia làm 3 giai đoạn:

```text
Giai đoạn 1: Token đầu vào (Input Tokens)
  System Prompt + Cửa sổ ngữ cảnh (Context Window) + Tin nhắn người dùng
  ↓
[LLM Suy luận]
  ↓
Giai đoạn 2: Token đầu ra (Output Tokens)
  Câu trả lời do mô hình sinh ra + Quá trình suy nghĩ (Thinking process)
  ↓
Giai đoạn 3: Lịch sử tin nhắn vòng kế tiếp
  Ghi nhận hội thoại vòng này vào phiên, trở thành ngữ cảnh đầu vào cho vòng sau
  (→ Quay trở lại Giai đoạn 1)
```

**Quan sát mấu chốt**: Phiên càng kéo dài, cửa sổ ngữ cảnh càng phình to, lượng Token đầu vào ở mỗi vòng sau càng lớn. Điều này tạo nên **sự tăng tốc chi phí**: Lượng Token đầu vào ở vòng đối thoại thứ 10 thường gấp 5 đến 10 lần so với vòng đối thoại đầu tiên.

### 14.1.2 Tối ưu hóa Token đầu vào (Input Tokens)

#### 1. Tinh gọn Prompt hệ thống (System Prompt)

Prompt hệ thống là chi phí cố định bắt buộc phải gửi đi ở mỗi vòng suy luận.

**Trước khi tối ưu** (Cách viết rườm rà thường thấy):
```text
Bạn là một trợ lý chăm sóc khách hàng. Trách nhiệm của bạn là giúp đỡ người dùng giải quyết vấn đề.
Bạn cần luôn giữ thái độ thân thiện và chuyên nghiệp.
Bạn tuyệt đối không được đưa ra lời khuyên y tế.
Bạn cần giải quyết thắc mắc của người dùng càng nhanh càng tốt.
... [kèm theo 20 dòng mô tả tương tự] ...
```

**Sau khi tối ưu** (Bản tinh gọn):
```text
Trợ lý CSKH. Thân thiện, chuyên nghiệp, từ chối tư vấn y tế.
```

**Hiệu quả**: Tiếng Việt/tiếng Anh rút gọn từ hàng trăm từ xuống chỉ còn vài từ ngắn gọn, tiết kiệm hàng triệu Token mỗi tháng cho quy mô hàng ngàn lượt đối thoại.

#### 2. Phân bổ công cụ khác biệt hóa theo từng Agent

Không phải Agent nào cũng cần toàn bộ danh mục công cụ. Thu hẹp danh sách công cụ giúp giảm đáng kể phần định nghĩa schema công cụ trong prompt.

**Trước khi tối ưu** (Nhồi danh sách công cụ dùng chung):
```jsonc
{
  "tools": [
    "web_search", "send_email", "create_calendar_event",
    "read_file", "write_file", "delete_file",
    "query_database", "execute_sql", "call_api"
    // ... phía dưới còn hơn 20 công cụ nữa
  ]
}
```

**Sau khi tối ưu** (Phân bổ chính xác theo chức năng từng Agent):
```json
{
  "agents": {
    "support_agent": {
      "tools": ["search_knowledge_base", "send_email", "create_ticket"]
    },
    "data_analyst": {
      "tools": ["query_database", "execute_sql", "plot_chart"]
    }
  }
}
```

#### 3. Ngân sách cửa sổ ngữ cảnh & Cắt tỉa động

Ngay cả khi mô hình hỗ trợ cửa sổ 100K–1M Token, bạn cũng không nên nhét toàn bộ lịch sử vào từng lượt gọi. Điểm mấu chốt là **nạp có chọn lọc**.

Ví dụ cấu hình:
```json
{
  "agents": {
    "defaults": {
      "contextTokens": 10000,
      "contextPruning": {
        "mode": "cache-ttl",
        "ttl": "5m"
      }
    }
  }
}
```

Nhờ cơ chế khử trùng lặp và cắt tỉa thông minh, thông thường có thể hạ ngữ cảnh từ 15K xuống còn 8K Token mà vẫn giữ nguyên chất lượng phản hồi.

### 14.1.3 Tối ưu hóa Token đầu ra (Output Tokens)

#### 1. Giới hạn độ dài đầu ra (maxTokens)

Đối với các tác vụ không đòi hỏi câu trả lời dài dòng, hãy thiết lập giới hạn rõ ràng:

```json
{
  "agents": {
    "defaults": {
      "models": {
        "anthropic/claude-sonnet-4-6": {
          "params": { "maxTokens": 500 }
        }
      }
    }
  }
}
```

#### 2. Định dạng đầu ra có cấu trúc (Structured Output)

Sử dụng JSON Schema giúp mô hình sinh câu trả lời cô đọng, tránh các câu chữ chào hỏi rườm rà.

**Trước khi tối ưu** (Văn bản tự do - ~150 Token):
```text
Khách hỏi: "Bưu kiện của tôi đang ở đâu?"
Mô hình trả lời: "Kính chào quý khách! Bưu kiện của quý khách hiện đang nằm tại trạm trung chuyển. Căn cứ theo hệ thống theo dõi của chúng tôi, đơn hàng (mã số: 12345678) đã đến trạm trung chuyển Hà Nội vào lúc 10:30 sáng nay. Dự kiến sẽ được giao vào chiều mai. Nếu có bất kỳ thắc mắc nào, quý khách vui lòng liên hệ lại với chúng tôi bất cứ lúc nào."
```

**Sau khi tối ưu** (Cấu trúc JSON - ~30 Token):
```json
{
  "status": "in_transit",
  "location": "Hanoi Hub",
  "eta": "2026-03-23T18:00Z",
  "order_id": "12345678"
}
```

### 14.1.4 Chiến lược nén và cắt tỉa ngữ cảnh

Khi phiên đối thoại kéo dài, bắt buộc phải chủ động nén để tránh bùng nổ chi phí:

#### Chiến lược 1: Thu gọn & Tóm tắt (Compaction)

Gộp nhiều tin nhắn cũ thành một tin nhắn tóm tắt cô đọng:

```text
[Tóm tắt trao đổi trước đó] Khách hàng hỏi tính năng sản phẩm A, giá ($99), ưu đãi (giảm 20%), thời gian giao hàng (3-5 ngày). Khách bày tỏ sự quan tâm. Tin nhắn gần nhất: Khách hỏi khi nào có hàng.
```

Ví dụ cấu hình:
```json
{
  "agents": {
    "defaults": {
      "compaction": {
        "mode": "safeguard",
        "keepRecentTokens": 5000,
        "model": "<provider/low-cost-model>",
        "truncateAfterCompaction": true,
        "maxActiveTranscriptBytes": 10485760
      }
    }
  }
}
```

#### Chiến lược 2: Cắt tỉa theo độ ưu tiên (Pruning)

- Luôn giữ lại 5 tin nhắn gần nhất (ngữ cảnh trực tiếp).
- Giữ lại các tin nhắn được đánh dấu nhãn "quan trọng".
- Xóa các dòng log gỡ lỗi quá 7 ngày trước.
- Loại bỏ các cuộc thảo luận về những vấn đề đã được giải quyết xong.

### 14.1.5 Ảnh hưởng của việc lựa chọn mô hình lên bài toán chi phí

Các dòng mô hình có sự chênh lệch giá cước Token rất lớn.

**Bảng so sánh chi phí (Đơn giá tham khảo trên 1 triệu Token - 1M Tokens):**

| Dòng mô hình | Đơn giá đầu vào | Đơn giá đầu ra | Đặc tính | Kịch bản áp dụng tối ưu |
|---|---|---|---|---|
| **Claude Haiku 4.5** | $1 / 1M | $5 / 1M | Rất nhanh, chi phí siêu rẻ | Phân loại đơn giản, tóm tắt văn bản |
| **Claude Sonnet 4.6** | $3 / 1M | $15 / 1M | Cân bằng hoàn hảo, Adaptive Thinking | Trợ lý đa năng, tác vụ tiêu chuẩn |
| **Claude Sonnet 5.5** | $2 / 1M | $10 / 1M | 1M Context, 128K Output, Adaptive Thinking | Model chủ lực dòng Sonnet hiện hành |
| **Claude Opus 5.5** | $4 / 1M | $20 / 1M | 1M Context, 128K Output, suy luận sâu | Lập trình chuyên sâu, tri thức dài hạn |
| **GPT-5.5** | $5 / 1M | $30 / 1M | Tầng suy luận cao cấp của OpenAI | Bài toán hóc búa, phân tích phức tạp |
| **GPT-5.4** | $2.50 / 1M | $15 / 1M | Dòng chủ lực thông dụng của OpenAI | Suy luận tổng quát |
| **GPT-5.4 mini** | $0.75 / 1M | $4.50 / 1M | Hiệu năng/chi phí rất tốt | Tải cao, cần độ trễ thấp |
| **GPT-5.4 nano** | $0.20 / 1M | $1.25 / 1M | Chi phí cực thấp | Tác vụ đơn giản, gọi tần suất cao |

Chiến lược phân tầng điển hình: 80% câu hỏi đơn giản → Dùng Haiku/Mini; 15% tác vụ bậc trung → Dùng Sonnet/GPT-5.4; 5% tác vụ cực khó → Dùng Opus/GPT-5.5. Mô hình này giúp hạ tổng chi phí trung bình từ 50% đến 70%.

### 14.1.6 Đo lường chi phí Token & Hạn mức

Các câu lệnh tích hợp sẵn của OpenClaw để kiểm tra lượng dùng:

```bash
# Xem tóm tắt Token / Cache / Chi phí lượt trả lời gần nhất của phiên hiện tại
/status

# Xem tóm tắt chi phí của phiên làm việc
/usage cost

# Xem tóm tắt chi phí qua CLI dựa trên tệp transcript
openclaw gateway usage-cost

# Xem bản chụp hạn mức và cửa sổ tiêu thụ phía nhà cung cấp
openclaw status --usage
```

### 14.1.7 Checklist kiểm tra tối ưu hóa chi phí

1. **Độ dài System Prompt** < 100 từ? □ (Nếu chưa: tinh gọn xuống dưới 50 từ).
2. **Số lượng công cụ** < 5 công cụ/Agent? □ (Nếu chưa: phân bổ riêng theo từng agent).
3. **Ngân sách Context** < 10K Token? □ (Nếu chưa: bật `contextPruning` hạ xuống 8K).
4. **Lịch sử tin nhắn** < 20 tin? □ (Nếu chưa: bật `compaction` nén lại).
5. **Giới hạn đầu ra** đã thiết lập? □ (Nếu chưa: đặt `maxTokens` cho từng model).
6. **Mô hình** đã phân tầng chưa? □ (Nếu chưa: việc dễ dùng model nhẹ, việc khó dùng model lớn).

Hoàn thành 6 mục trên thông thường sẽ giúp bạn cắt giảm từ 40% đến 60% hóa đơn Token.
