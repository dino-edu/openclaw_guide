## 14.3 Quan sát mức tiêu thụ & Kiểm soát ngân sách trên OpenClaw

Mục này hướng dẫn cách sử dụng các câu lệnh tích hợp sẵn của OpenClaw cùng trang `Control -> Usage` trên Dashboard để thực hiện **quan sát lượng dùng theo thời gian thực (hoặc gần thực)**, kết hợp trang quản trị của nhà cung cấp mô hình, hệ thống giám sát ngoài hoặc plugin tùy biến để **quản trị ngân sách**, ngăn ngừa nguy cơ chi phí bùng nổ ngoài tầm kiểm soát.

### 14.3.1 Các câu lệnh quan sát cốt lõi

OpenClaw cung cấp nhiều câu lệnh tích hợp để chẩn đoán lượng dùng. Nếu bạn thích giao diện đồ họa trực quan, trang `Control -> Usage` trên Dashboard hiển thị biểu đồ Token, chi phí và phân bổ phiên theo từng khung thời gian.

#### Lệnh `/status`

Xem mô hình hiện tại, cửa sổ ngữ cảnh, lượng Token của câu trả lời gần nhất và chi phí ước tính của câu trả lời đó:

```bash
/status
```

Đầu ra mẫu:
```text
Session: main
Model: anthropic/claude-sonnet-4-6
Context: 64K / 1M
Last response: input 12,340 tokens, output 820 tokens
Estimated last-reply cost: $0.049
```

#### Lệnh `/usage cost`

Xem bản tóm tắt chi phí cục bộ ngay trong cửa sổ chat, thích hợp để kiểm tra nhanh mức độ tiêu hao ngân sách gần đây. Nếu cần xem bản tóm tắt chi phí qua CLI dựa trên tệp transcript, dùng `openclaw gateway usage-cost`; nếu muốn xem hạn mức/cửa sổ tiêu thụ của provider, dùng `openclaw status --usage`.

```bash
/usage cost
```

Đầu ra mẫu:
```text
💸 Usage cost
Session $0.049 · 13.2K tokens
Today $3.41
Last 30d $57.80
```

#### Lệnh `/compact`

Chủ động kích hoạt nén ngữ cảnh thủ công để thu hồi ngân sách Token:

```bash
/compact Tập trung vào các quyết định thiết kế API và các tác vụ chưa giải quyết xong
```

Đầu ra:
```text
Yêu cầu nén đã được gửi; cửa sổ lưu giữ mục tiêu được điều chỉnh qua agents.defaults.compaction.keepRecentTokens.
```

### 14.3.2 Cấu hình ngân sách & Cảnh báo

#### Giới hạn ngân sách toàn cục

> [!CAUTION]
> Đoạn cấu hình dưới đây phản ánh kiến trúc quản trị tổng thể, không phải toàn bộ đều là schema có sẵn trong `openclaw.json`. Các ngưỡng chi tiêu cứng trong sản xuất bắt buộc phải được thiết lập tại bảng điều khiển thanh toán/hạn mức (Billing/Quota) của nhà cung cấp mô hình, hoặc qua hệ thống giám sát ngoài.

```json
{
  "budget": {
    "daily": {
      "tokens": 1000000,
      "cost": 500,
      "requests": 100000
    },
    "monthly": {
      "tokens": 30000000,
      "cost": 15000
    }
  },
  "alerts": {
    "enabled": true,
    "thresholds": {
      "dailyTokens": 0.8,
      "dailyCost": 0.9,
      "monthlyTokens": 0.75
    },
    "channels": ["email", "slack"]
  }
}
```

**Ý nghĩa cấu hình**:
- Ngân sách ngày: 1 triệu Token hoặc $500 (chạm giới hạn nào trước sẽ kích hoạt).
- Điều kiện cảnh báo: Khi lượng Token ngày chạm 80%, chi phí ngày chạm 90%, hoặc Token tháng chạm 75%.
- Dùng `/status` và `/usage cost` để lấy tóm tắt chi phí phiên cục bộ; dùng `openclaw gateway usage-cost` để xem chi phí qua CLI; dùng `openclaw status --usage` để xem hạn mức provider.
- Dùng trang quản trị quota/billing của provider để đặt giới hạn cứng.
- Dùng Prometheus, Grafana, Loki hoặc Webhook để bắn cảnh báo tức thì.

#### Phân bổ ngân sách theo từng Agent

```json
{
  "agents": {
    "support_agent": {
      "budget": {
        "dailyTokens": 500000,
        "dailyCost": 250,
        "enforceLimit": true
      }
    },
    "research_agent": {
      "budget": {
        "dailyTokens": 200000,
        "dailyCost": 100,
        "enforceLimit": false
      }
    }
  }
}
```

### 14.3.3 Cơ chế quản trị ngữ cảnh

#### Tự động nén & Dọn dẹp

```json
{
  "agents": {
    "defaults": {
      "compaction": {
        "mode": "safeguard",
        "keepRecentTokens": 5000,
        "model": "<provider/low-cost-model>",
        "truncateAfterCompaction": true,
        "maxActiveTranscriptBytes": 10485760
      }
    }
  },
  "session": {
    "maintenance": {
      "pruneAfter": "30d"
    }
  }
}
```

#### Đặt lại phiên & Dọn dẹp tệp cũ

```bash
# Chủ động đặt lại phiên hiện tại (xóa ngữ cảnh, bắt đầu hội thoại mới)
/new

# Dọn dẹp hàng loạt các phiên đã hết hạn (xem thử trước)
openclaw sessions cleanup --dry-run

# Thực thi dọn dẹp thực tế
openclaw sessions cleanup --enforce
```

### 14.3.4 Các chiến lược kỹ thuật kiểm soát chi phí

#### Chiến lược 1: Phân tầng lựa chọn mô hình

Thay vì phụ thuộc vào cơ chế tự động đoán độ phức tạp chưa được tài liệu hóa, cách tiếp cận chuẩn mực là phân tách mô hình theo cổng vào, theo agent hoặc theo nhiệm vụ cụ thể:

```jsonc
{
  "agents": {
    "list": [
      {
        "id": "support_fast",
        "model": "<provider/low-cost-model>"
      },
      {
        "id": "support_deep",
        "model": "anthropic/claude-sonnet-4-6"
      }
    ]
  }
}
```

Ở phía cổng vào, bạn dùng channel bindings hoặc routing để chuyển các yêu cầu đơn giản sang `support_fast`, và chuyển các bài toán phân tích sâu sang `support_deep`.

#### Chiến lược 2: Caching công cụ & Khử trùng lặp

Việc lưu bộ nhớ đệm (Cache) cho các lượt gọi công cụ lặp lại nên được thực hiện tại plugin tùy biến hoặc API Gateway nghiệp vụ, đồng thời loại trừ rõ ràng các công cụ ghi có tác dụng phụ (như gửi email, tạo ticket):

```jsonc
{
  "// plugin_cache_policy": "Mô phỏng chính sách cache của plugin",
  "ttl": 3600,
  "keyStrategy": "hash(tool, args)",
  "excludeTools": ["send_email", "create_ticket"]
}
```

### 14.3.5 Phát hiện dị thường chi phí & Cảnh báo sớm

Mẫu quy tắc phát hiện dị thường tiêu thụ Token (qua hệ thống giám sát ngoài hoặc plugin):

```json
{
  "anomalyDetection": {
    "enabled": true,
    "baselines": {
      "averageDailyCost": 500,
      "stdDeviation": 100
    },
    "triggers": [
      {
        "name": "spike_detection",
        "condition": "dailyCost > baseline + 3 * stdDev",
        "action": "alert + pause_non_critical"
      },
      {
        "name": "model_drift",
        "condition": "error_rate > 5%",
        "action": "notify_admin"
      }
    ]
  }
}
```

### 14.3.6 Checklist kiểm tra lượng dùng & Kiểm soát ngân sách

Khi triển khai OpenClaw, đảm bảo hoàn tất:

- **Khả năng hiển thị**: Chạy `/usage cost` để xem tóm tắt phiên; dùng `openclaw gateway usage-cost` xem chi phí CLI; dùng `openclaw status --usage` kiểm tra hạn mức provider.
- **Kiểm soát ngân sách**: Thiết lập trần chi tiêu cứng trên trang quản trị của nhà cung cấp mô hình.
- **Tự động nén**: Cấu hình `agents.defaults.compaction` dựa trên cửa sổ ngữ cảnh thực tế của model.
- **Dọn dẹp phiên**: Chạy `openclaw sessions cleanup --dry-run/--enforce` và cấu hình `session.maintenance.pruneAfter`.
- **Phân tích chi phí**: Hàng tuần kiểm tra `openclaw gateway usage-cost` và trang Usage trên Dashboard để theo dõi xu hướng.
- **Phân tầng mô hình**: Chia tách mô hình theo Agent/Cổng vào để tối ưu hóa chi phí.
