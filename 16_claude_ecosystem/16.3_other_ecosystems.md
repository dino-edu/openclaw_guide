## 16.3 Tích hợp OpenAI & Mô hình cục bộ (Local LLM)

OpenClaw không bị trói buộc vào một nhà cung cấp AI duy nhất. Bên cạnh Claude, OpenAI cùng các mô hình chạy cục bộ đại diện bởi Ollama cũng là những sự lựa chọn phổ biến trong môi trường sản xuất. Mục này giới thiệu phương thức kết nối và cấu hình điển hình cho hai hệ sinh thái này, cũng như chiến lược kết hợp đa hệ sinh thái với Claude.

### 16.3.1 Kết nối mô hình OpenAI

OpenClaw kết nối với hệ sinh thái OpenAI qua các đường dẫn provider, auth profile và runtime khác nhau. Định danh mô hình OpenAI Agent sử dụng tiền tố chuẩn `openai/*`; việc xác thực thuê bao ChatGPT/Codex OAuth được thể hiện qua Codex/OpenAI auth profile và runtime.

#### Cấu hình cơ sở

```jsonc
{
  // API Key nạp qua biến OPENAI_API_KEY, onboarding hoặc auth profiles
  agents: {
    defaults: {
      model: {
        primary: "openai/gpt-5.5",
        fallbacks: ["anthropic/claude-sonnet-4-6"],
      },
    },
  },
}
```

#### Sử dụng Azure OpenAI Service

Khách hàng doanh nghiệp thường gọi mô hình GPT qua dịch vụ Azure OpenAI Service. Trên OpenClaw, các yêu cầu trò chuyện / Responses sử dụng `azure-openai-responses/<deployment>`:

```jsonc
{
  models: {
    providers: {
      "azure-openai-responses": {
        apiKey: "${AZURE_OPENAI_API_KEY}",
        baseUrl: "https://your-resource.openai.azure.com/openai/v1",
        api: "azure-openai-responses",
        models: [{ id: "<deployment>", name: "Azure GPT deployment" }],
      },
    },
  },
  agents: {
    defaults: {
      model: { primary: "azure-openai-responses/<deployment>" },
    },
  },
}
```

#### Các điểm lưu ý khi kết nối OpenAI

| Năng lực | Giải thích ý nghĩa |
|---|---|
| **Gọi công cụ (Function Calling)** | Tương thích tự nhiên với hệ thống công cụ của OpenClaw, định dạng được tự động chuyển đổi |
| **Đầu ra có cấu trúc** | Hỗ trợ `response_format: { type: "json_schema" }` phối hợp chặt chẽ với bộ phân giải đầu ra |
| **Dòng mô hình suy luận o-series** | Các model suy luận như `openai/o3` rất nhạy cảm với thứ tự prompt; quy tắc vai trò và ranh giới an toàn nên đặt ở developer message, chi tiết tác vụ đặt ở user message |
| **Embeddings** | OpenAI Embeddings API có thể kết nối qua MCP server hoặc công cụ tùy biến |

### 16.3.2 Mô hình cục bộ: Kết nối qua Ollama

Ollama là nền tảng chạy mô hình cục bộ hàng đầu hiện nay, hỗ trợ các mô hình mã nguồn mở như Llama, Mistral, Qwen, DeepSeek... Ưu thế tuyệt đối của việc triển khai cục bộ là dữ liệu không rời khỏi mạng nội bộ, không tốn chi phí gọi API, cực kỳ phù hợp cho các bài toán nhạy cảm về quyền riêng tư hoặc môi trường mạng bị cô lập hoàn toàn.

#### Nguyên lý kết nối

OpenClaw khuyến nghị ưu tiên nhận diện Ollama qua luồng `openclaw onboard` / tự động khám phá mô hình. **Tuyệt đối không trỏ OpenClaw tới đường dẫn `http://localhost:11434/v1` tương thích OpenAI**; tài liệu chính thức cảnh báo việc này sẽ làm hỏng cơ chế gọi công cụ gốc, khiến mô hình xuất JSON của công cụ ra dưới dạng văn bản thuần. Hãy sử dụng trực tiếp địa chỉ API gốc của Ollama:

```jsonc
{
  models: {
    providers: {
      ollama: {
        baseUrl: "http://localhost:11434",
        apiKey: "ollama-local", // Chạy nội bộ LAN thường không cần bearer token thật
        api: "ollama",
        models: [
          {
            id: "gpt-oss:20b",
            name: "GPT-OSS 20B",
            input: ["text"],
            cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 },
            contextWindow: 128000,
            maxTokens: 8192,
          },
        ],
      },
    },
  },
  agents: {
    defaults: {
      model: {
        primary: "ollama/gpt-oss:20b",
      },
    },
  },
}
```

#### Cài đặt Ollama & Tải mô hình

```bash
# Cài đặt Ollama (trên macOS qua Homebrew)
brew install ollama

# Khởi động dịch vụ nền
ollama serve

# Tải mô hình về máy (ví dụ GPT-OSS 20B)
ollama pull gpt-oss:20b

# Kiểm tra dịch vụ hoạt động
curl http://localhost:11434/api/tags
```

#### Bảng tham chiếu lựa chọn mô hình cục bộ & Nhu cầu VRAM

| Mô hình | Số lượng tham số | Kịch bản áp dụng tối ưu | Nhu cầu bộ nhớ VRAM |
|---|---|---|---|
| `llama3.1:8b` | 8B | Hỏi đáp nhanh, trợ lý thông thường | ~6 GB |
| `llama3.3:70b` | 70B | Suy luận tổng quát chất lượng cao | Tùy lượng tử hóa, cần VRAM lớn |
| `gpt-oss:20b` | 20B | Suy luận tổng quát, gọi công cụ | ~16 GB+ |
| `qwen2.5-coder:32b` | 32B | Sinh mã nguồn, review code | ~20 GB |
| `deepseek-r1:32b` | 32B | Suy luận toán học & logic phức tạp | ~20 GB |

### 16.3.3 Chiến lược hỗn hợp đa hệ sinh thái (Hybrid Strategy)

Trong thực tế sản xuất, việc kết hợp linh hoạt nhiều hệ sinh thái giúp tối ưu hóa cả chất lượng lẫn chi phí:

#### Cấu hình hỗn hợp điển hình

```jsonc
{
  agents: {
    entries: {
      chat: {
        // Đối thoại thông thường: Dùng mô hình local để triệt tiêu chi phí
        model: {
          primary: "ollama/gpt-oss:20b",
          fallbacks: ["openai/gpt-5.4"],
        },
      },
      dev_assistant: {
        // Suy luận phức tạp và viết code: Dùng Claude Sonnet
        model: {
          primary: "anthropic/claude-sonnet-4-6",
          fallbacks: ["openai/gpt-5.4"],
        },
      },
      classifier: {
        // Tác vụ phân loại nhẹ tần suất cao: Dùng model độ trễ thấp
        model: {
          primary: "<provider/low-latency-model>",
        },
      },
    },
  },
}
```

#### Bảng tham chiếu chiến lược hỗn hợp

| Chiến lược | Mô hình chính (Primary) | Mô hình dự phòng (Fallback) | Kịch bản áp dụng |
|---|---|---|---|
| **Ưu tiên quyền riêng tư** | Cục bộ (Ollama) | `anthropic/claude-sonnet-4-6` | Dữ liệu nhạy cảm không rời khỏi máy |
| **Ưu tiên chi phí** | Cục bộ (Ollama) | Model nhẹ độ trễ thấp trong catalog | Tải cao, logic nghiệp vụ đơn giản |
| **Ưu tiên chất lượng** | `anthropic/claude-sonnet-4-6` | `openai/gpt-5.5` | Đòi hỏi chất lượng suy luận cao nhất |
| **Dự phòng offline** | `anthropic/claude-sonnet-4-6` | Cục bộ (Ollama) | Môi trường mạng chập chờn, hay mất kết nối |

### 16.3.4 Quản trị thống nhất đa hệ sinh thái

Giao diện quản trị của OpenClaw cung cấp góc nhìn thống nhất xuyên suốt mọi nhà cung cấp. Kiểm tra trạng thái toàn bộ các mô hình đã cấu hình qua lệnh:

```bash
openclaw models status --probe
```

Khuyến nghị vận hành hỗn hợp:
1. Cấu hình biến môi trường `apiKey` độc lập cho từng nhà cung cấp, tránh dùng chung khóa bí mật.
2. Định kỳ chạy đầu dò probe với mô hình cục bộ để đảm bảo tiến trình Ollama luôn sống.
3. Đồng bộ các ngưỡng cảnh báo hạn mức của từng provider về cùng một hệ thống giám sát tập trung.
